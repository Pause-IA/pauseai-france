Charte graphique

Les couleurs, la typographie et les briques d’interface du site Pause IA — et les quelques règles qui les tiennent ensemble.

Source de vérité : src/app.css. Ce document en est le reflet lisible ; en cas d’écart, c’est le code qui a raison. Version longue et à jour : docs/charte-graphique.md.

1.Le principe

Tout est écrit en variables CSS (des « tokens »). Une page qui n’utilise que ces variables fonctionne en mode clair comme en mode sombre sans une ligne de plus, et suit automatiquement toute évolution de la charte.

La règle unique

Jamais de couleur en dur dans une page. #ff9416 s’écrit var(--brand). Le linter (pnpm lint) refuse le reste.

2.Couleurs de marque

#ff9416
--brand Aplats : boutons, filets, puces, bordures. Sombre : identique.
#fff5e8
--brand-light Fond orangé très clair, mises en avant. Sombre : #2a1f0a.
#a85400
--brand-subtle Le seul orange lisible en texte : liens, chiffres, sur-titres. Sombre : #ffab40.
Contraste

--brand n’a jamais un contraste suffisant pour du texte (2,2:1 sur le crème). Pour un lien ou un chiffre, c’est --brand-subtle (4,9:1) ; sur un aplat orange, c’est --on-brand (7,9:1), jamais du blanc.

Texte posé sur l’orange

Un fond orange ne change pas en mode sombre : le texte qu’il porte non plus. D’où deux tokens dédiés, --on-brand (#1a1a1a) et --on-brand-muted (#3a2600), à utiliser au lieu de « noir ».

Pourquoi un blanc cassé

Le fond de page est crème sur toutes les pages sauf l’accueil. Les cartes prennent donc un blanc chaud (--bg-card) : un gris froid posé sur ce crème se voit immédiatement.

4.Couleurs d’état

Le vert et le rouge signalent un état — inscription réussie, paiement refusé. Un badge décoratif prend l’orange de marque, jamais une couleur d’état.

Brand Neutral Outline Succès Erreur

--success #2e7d32 #6fcf7e Texte de confirmation
--error #c0392b #ff8a7a Texte d’erreur
--alert #d92d20 #ff6b5e Moment critique d’une chronologie, rien d’autre

Chaque état a aussi son fond et sa bordure : --success-bg, --success-border, --error-bg, --error-border.

5.Typographie

Deux polices. Libre Franklin pour les titres (--font-heading) : lignée Franklin Gothic, chasse étroite, proche du poids du logo. Inter pour le texte (--font-body), dessinée pour l’écran.

Graisses chargées : Libre Franklin 600, 700, 800 ; Inter 400, 500, 600, 700, et les italiques 400 et 700. N’employer que celles-là : une graisse absente est fabriquée par le navigateur en épaississant le trait, une italique absente en penchant le romain.

h1 — 700 / 2rem Reprendre le contrôle
h2 — 700 / 1.7rem Nos analyses
h3 — 500 / 1.5rem Ce que nous demandons
italique — 400 Une vraie italique, pas un romain penché.
chapô — --text-2 Une ou deux phrases qui éclairent le titre.
corps — 1.2rem / 1.5 Le texte courant, avec un lien souligné en orange foncé.

Sur les pages campagne, les titres respirent : clamp(2rem, 5.5vw, 3rem) pour le h1. La typographie française est appliquée automatiquement au Markdown — espace fine insécable avant ; ? ! %, insécable avant :, guillemets « ».

  • Largeurs : --width-text 44 rem (corps de texte), --width-content 54 rem (pages éditoriales et campagnes), --width-wide 66 rem (grilles).
  • Ombres : --shadow-card très discrète sur les encadrés, --shadow-raised au survol d’une carte cliquable, --shadow-brand sur le bouton principal. Renforcées en mode sombre.
  • Cibles tactiles : 48 px de haut au minimum pour un bouton.
  • Gouttière : 1,5 rem, 1,1 rem en mobile.

7.Briques réutilisables

Bouton principal Bouton secondaire

Card Carte de la charte — default, accent, plain
Badge Pastille — brand, neutral, outline, success, error
PageHero Filet de marque, titre, chapô, actions
SectionTitle Titre de section avec pastille de compte
FilterChips Barre de filtres en pilules

Elles vivent dans $components/ui. Les pages campagne ont en plus leur module dédié, $components/campaign, construit sur les mêmes tokens — voir /fr/campagne-modele.

Motifs récurrents : filet de marque au-dessus d’un titre de hero (3 rem × 4 px, arrondi), titre souligné d’un dégradé orange, callout à bordure orange, citation à barre gauche, chronologie à axe vertical orange.

8.Mode sombre

Piloté par data-theme="dark" sur <html>, posé avant le premier rendu pour éviter le flash. Une page qui n’utilise que des tokens n’a rien de spécifique à écrire. Les intégrations tierces (iframes) doivent en revanche recevoir le thème explicitement.

9.Accessibilité

  • Mouvement réduit respecté globalement (prefers-reduced-motion).
  • Focus visible conservé sur tous les éléments interactifs.
  • Toute iframe porte un title descriptif.
  • Pas de texte justifié : sans césure fiable, il creuse des rivières de blancs.

10.En pratique

À faire

  • color: var(--text)
  • background: var(--bg-card)
  • border-radius: var(--radius-md)
  • Partir de Card et Badge
  • Vérifier la page dans les deux thèmes

À éviter

  • color: #111, color: white
  • var(--text, #111) — le repli masque le token
  • Un vert ou un rouge décoratif
  • Une énième variante de carte locale
  • text-align: justify
Contrôle automatique

pnpm lint lance stylelint : couleur en dur, couleur nommée et texte justifié sont refusés. Le hook de pre-commit le lance sur les fichiers modifiés. Les seules exceptions, déclarées dans .stylelintrc.json : app.css (la palette), la palette Wait But Why, le logo et les drapeaux SVG.
